# 从旧版迁移到原生重写版

## 数据迁移范围

新版使用独立应用标识、独立 Release 签名和应用沙箱。Release 为 `app.zhinengtika.nativeapp`，Debug 为 `app.zhinengtika.nativeapp.debug`。它没有直接读取旧应用私有目录的权限，也没有自动导入旧配置、账号、Temp 缓存或历史的通道。

当前源码提供以下手动路径，具体设备操作尚未执行：

1. **重新登录自己的学生账号**：在“账号”页登录，服务返回的会话经 Android Keystore AES-GCM 保存；密码不持久化。不要复制旧配置中的明文密码、token、session 或实名资料。
2. **导入自有题卡**：首页进入“离线资料库”，通过系统文件选择器导入自己有权使用的 JSON；缺少编号的旧格式可用文件名或界面中的备用编号补充。解析会校验 UTF-8、大小、编号、深度和题数，白名单重建题卡，移除历史答卷与账号元数据。
3. **导入目录**：可导入旧格式的“名称一行、编号一行”目录文本，并指定学科标记；支持题名、编号、学科筛选。目录记录只用于本机检索，不包含题卡正文，也不会产生在线提交权限。

导入题卡与合成演示示例始终是**只读离线内容**：详情不传入账号，无“作业”页，不上传图片、不提交答卷、不请求远端题图。可在全部/逐题、解析、答案、原题间查看，或导出不含历史作答的 HTML；导出文件内 HTTPS 图片引用并未打包为离线图片，使用外部浏览器打开时可能请求这些引用。

单个导入文件上限为 8 MiB；离线库限制 100 张卡、题卡 JSON 合计 16 MiB、目录 10,000 条。原文件不因导入或删除本机副本而被修改。格式和隐私规则见[协议说明](protocol.md)与[隐私说明](privacy.md)。

## 不自动迁移的旧内容

| 旧数据或能力 | 新版处理与原因 |
|---|---|
| 公共账号 token/session/studentId | 不内置、不迁移；旧资源中的共享会话不是稳定公开 API 或可再分发授权 |
| 旧配置中的密码与会话 | 不导入；自己的账号需重新登录，密码不保存 |
| 旧 detailData / 实名学校资料 | 不导入；新版只保留协议需要的最小账号字段 |
| 私有 Temp 历史与题卡文件 | 不能跨包自动读取；用户手动取得且有权使用的文件可导入只读库，旧历史文本可作为离线目录导入，不冒充某账号的在线访问历史 |
| 内置题库、学科列表、微软雅黑字体 | 未取得明确再分发许可，不随包提供；使用系统字体和合成示例 |
| 第三方二维码凭据与压缩设置 | 不迁移；扫码改为 CameraX + ZXing 本机解码 |
| 字体、字号、小字、latest 列表偏好 | 不迁移；提供系统/浅色/深色主题，没有独立字体/字号设置 |
| QML style、背景图 URL、公告已读 | 不迁移；背景图源与公告未实现 |
| 学案资源下载 | 未实现；上游随机授权和固定学校编号不能作为有效认证依据 |
| 旧 GitHub Qt 更新源 | 不接入；旧源发布的 Qt APK 不是本版安装包，尚未配置原生版独立更新源 |
| 原始答卷 JSON 手工编辑 | 未实现；答卷由已校验模型生成，提交仍需确认 |
| 旧应用包名与签名私钥 | 不复用；新旧身份独立，不把旧私钥带入新工程 |

业务差异详见[功能对照](feature-comparison.md)，旧内容许可依据见[第一阶段许可审计](audit/toolchain-licenses.md)。

## 新版自身数据的保存与清除

在线缓存、最近访问、草稿和未知提交标记按学校/学生身份作用域隔离。主页可按历史题名或编号筛选；切换账号会取消并丢弃过期加载结果。旧全局历史不会自动成为新账号历史。

在线作答草稿加密保存。当前实现包含去抖写入、返回前等待最后快照保存、生命周期停止时刷新，以及共同 Mutex 防止旧写入覆盖新快照；保存失败可重试或明确选择不保存离开。相册照片只有成功取得持久读取权限后才记入草稿；打开相册期间若页面重建而丢失题目上下文，会显示重选提示，需要重新选择本次照片。即使已有权限，原图被用户删除或提供方撤销访问后仍可能无法读取。后台、重启、快速返回与授权恢复均尚未真机验证。

“设置 → 清除在线缓存与历史”单独确认后只删除在线题卡副本和最近访问，不退出账号、不撤回已提交答卷、不删除草稿或未知提交标记。“清除离线资料库”另行确认后删除导入/演示卡与目录；逐条删除也会确认，只影响本机副本。退出当前账号移除该会话，缓存保留。卸载会失去本版私有数据和 Keystore 密钥；本版关闭备份，并对 Android 12+ 云备份/设备迁移作排除配置，不能依赖系统迁移恢复加密数据。

## 安装、签名与实际验证状态

最终源码状态已生成 Debug、签名 Release 和 instrumentation 测试 APK，三者通过静态签名、包名/版本、最低 API 26 / 目标 API 35、ZIP 完整性及对齐检查；Release 与 Debug 证书独立，测试 APK 与 Debug 证书相同。Release 私钥保存在源码工程之外，不含于交付源码或公共下载包。后续更新本版需要保留同一 Release 身份，不能以旧版私钥或新生成密钥替代。

包含最后修正的最终签名构建及产物复核已成功。独立包名支持共存是设计与元数据事实，本次没有实际安装、启动或旧新版共存测试。此前手机 shell 返回 `shizukuStopped`，本轮只读探测返回 `cancelled`、`started:false`，均没有命令执行；读屏仍报告无障碍不可用。设备和真实服务端路径仍未执行。两个 Compose 测试已编译，未运行；32 个 JVM 合成测试通过不代表线上登录或作业提交验证。

首次使用可先在无需账号的离线库载入标明“非真实题目”的合成示例。在线登录、查询、上传和不可撤回答卷提交均须使用自己的有效授权；本任务没有执行这些真实 API 操作。出现“提交结果未知”时，应先到服务端人工核实，再考虑解除本机标记，不能把未知视为失败而直接重发。

构建、最终产物与测试证据见[构建说明](../BUILDING.md)、[测试报告](../TESTING.md)和[已知问题](known-issues.md)。
