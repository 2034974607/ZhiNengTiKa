# 设备验收执行方案

## 当前结果与方法

2026-11-28 已完成一次独立限定 Android user0 的受限真机验收：修复测试依赖后两个 Debug Compose 测试实际通过；最终 Release 的离线合成题卡、系统文件选择器取消返回、基础启动/PSS 和初始帧记录已有证据，见[真机总结](device-results-20261128.md)。真实账号、上传提交、相机、完整文件读写和复杂生命周期仍待验证。

本次设备是 OPPO PHY120 / Android 17 / API 37，另有 user999（MultiApp），Release/Debug 原本已在 user0 安装。用户重新明确授权后，经手机工具和 Shizuku shell（uid0）逐步核对用户、包摘要与 Debug 空状态，在保留数据的前提下安装/更新测试包和更新 Release。三个包不在 user999 安装；没有卸载或清数据。每次应用操作明确限定 user0，未测试 user999。

[通用验收脚本](../tools/acceptance-device.py)的执行条件仍是干净单用户设备，**本次没有执行该脚本或旧 48 条计划**。这些守卫只约束该脚本，并不把具备明确授权、包和数据核对的独立受限验收判为不可行；也不能通过关闭守卫将本次记录冒充脚本完成。

## 通用脚本的准备条件

- 自己控制的 Android 8.0 / API 26 及以上测试设备，屏幕已解锁，当前 Android 用户为 0 且只有这个用户；工作资料、访客或其他用户设备由脚本拒绝。
- 已通过正常开发者流程授权主机的 ADB，自行确定 serial。脚本不负责配对、连接、重连或恢复手机操控。
- 设备内没有本版 Release、Debug 和测试包，包括卸载后保留数据。三个包查询均通过后才安装；脚本不覆盖已有包、不卸载、不清数据。
- 完整解压交付目录内有三个 APK 与静态核验报告。源码 ZIP 本身不含 APK。
- 设备操作必须处于用户授权范围内。取消、超时或结果未知时，先核实现状，不能自动重放、改写或切换后端执行。

不满足以上条件时，脚本应停止。维护者可以选择另一台合适测试设备；不得为通过守卫而删除用户数据。已有安装或多用户设备上的独立验收，需要单独审查实际用户、安装包身份和数据状态，保留自己的执行证据。

## 默认只生成计划

在源码根目录运行，替换实际交付目录：

```sh
python3 tools/acceptance-device.py \
  --delivery /path/to/unpacked-delivery \
  --output /path/to/new-acceptance-plan.json
```

默认模式只核对三个 APK 的 SHA-256、静态核验标记和 API 范围，不启动 ADB。输出文件必须不存在；结果的 `kind` 为 `device-acceptance-plan`，`status` 为 `plan-only`，`deviceTestsExecuted` 为 `false`，`commands` 为空，待执行命令在 `plan` 数组。`DEVICE_SERIAL` 是占位符，移动目录或更换机器后应重新生成。交付报告内的默认计划不是已执行结果。

仅在明确授权、满足通用脚本准备条件的设备上显式执行：

```sh
python3 tools/acceptance-device.py \
  --delivery /path/to/unpacked-delivery \
  --serial YOUR_DEVICE_SERIAL \
  --adb /path/to/host-compatible/adb \
  --run \
  --output /path/to/new-device-result.jsonl
```

不指定 `--adb` 时优先 PATH 中的 adb；ARM64 本机构建环境可用现有静态工具。不同宿主应选择匹配的工具，脚本不会下载或主动启动替代服务器；执行 adb 本身可能启动正常本地服务。默认每组采样五次，可选 3–20 次。上述命令不是本轮实际执行方式。

## 执行范围与记录解释

1. 核对 serial、当前用户 0 和单用户状态，读取厂家、型号、Android/API、电池上下文。
2. 先在主机私有临时目录复制并复核 APK 摘要，再查询三个包（含保留数据）均不存在后一次性安装；明确用户 0，不带替换或自动授予权限参数。
3. 运行确切 `AppNavigationTest` 类，核对两个方法的开始/成功状态、类与计数、`OK (2 tests)` 和最终终止码；不只依赖命令退出码。
4. 逐次 force-stop、确认进程冷启动并记录系统 `am start -W` 输出；Home 返回前台前后核对 PID，系统明确为 COLD 时不归为同进程返回。
5. 记录一次 PSS 和初始页面 `gfxinfo ... framestats` 原文。

两个测试只操作登录表单导航与合成离线示例，不输入凭据或触发线上业务。应用启动会读取自己保存的加密账号；有保存账号时还会读取历史。载入示例会在 Debug 离线库创建或刷新 `demo-builtin-001`，并重写题卡加密记录，示例保留。因此测试前应核实 Debug 的异步账号加载已经完成，未登录、无已保存账号，离线库为空或只有确认的合成示例，且没有解密/存储错误。Release 的空状态不能证明 Debug 的状态；不能通过登出、清数据或删除未知资料制造前提。

运行记录为追加式 JSONL，每个非空行是当时的完整快照；读取最后一个可解析完整对象确定最新状态。命令启动前先落盘 `in-progress`，完成或异常后再记快照。强杀或存储失败时停留在 `in-progress` 应按未知处理。非零退出、缺成功标志、已有包、测试失败或关键数据不完整均停止后续步骤。超时、Ctrl-C 或 SIGTERM 后设备动作仍可能继续；先核实，不重试、不重连、不切换通道。已安装包、合成示例和主机 APK 快照保留。

`scripted-checks-complete` 只表示自动步骤完成。`deviceTestsExecuted` 仅表示观察到至少一个预期测试开始，不等于全部通过；非零退出/超时保留已观察计数并强制 `instrumentation.complete: false`。未知结果且没有开始输出时，`deviceTestsExecuted: false` 也不能证明设备端没执行。完整判定需结合终态、原始输出、每条状态和 `commandResultUnknown`。

## 性能字段与主机检查

冷启动与返回前台分别汇总 `TotalTime` / `WaitTime`。若系统明确“当前任务已带回前台”、状态和组件正确且 PID 连续，仅提供 `WaitTime`，可以记录任务返回，缺失的 `TotalTime` 保留为 null，不能填成 0 或命名为温启动/渲染时间。本轮最终五个返回样本均为这种情况；`LaunchState: UNKNOWN (0)` 保留原样。

进程冷启动不清磁盘缓存，不代表安装后首次启动或 fully drawn；PSS 是一次快照，初屏帧记录不是长列表滚动 benchmark。电池/温度是上下文，不能直接推导 App 耗电或温升。具体原始值和限制见[性能报告](../PERFORMANCE.md)。

[主机合成检查](../tools/check-device-acceptance.py)本轮 41 项通过、启动 ADB 进程数为 0；验证解析、执行守卫、取消/错误停止及缺失时序字段，结果在交付报告 `evidence/device-runner-selfcheck.json`。合成检查与默认计划均不增加设备测试通过数。本次真机原始证据另在 `evidence/device-20261128/`，旧失败、修复后成功和未执行计划分开保存。

## 后续人工验收

本轮 Release 已观察离线合成示例和父子题显示、更新/冷启动后保留、导入与导出选择器打开/取消返回；未进行实际文件读写。后续仍需在授权范围内验证：

- 完整 SAF 导入/导出及取消之外的错误恢复，含合成文件和原文件不变。
- 浅深色、大字体、横竖屏及最低 API 设备。
- 相机授权拒绝/恢复、切镜头和合成二维码。
- 在线草稿、进程重建、URI 权限恢复和相册重选提示。
- 多账号隔离、清理范围、提交确认与 UNKNOWN 保护。

详见[测试清单](../TESTING.md)。真实服务互操作需要单独获授权的账号、题卡和测试作业，不使用真实不可撤回答卷做压测。本轮没有触发线上业务，也没有抓包，不能据此声明已验证零网络。设备记录可能含型号和本机路径，外发前人工检查。
